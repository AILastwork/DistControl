DiskControl

Инструкция по текущей версии: пользовательская утилита, админская утилита, файл доступа allow.json, служба dkclient и корректное отображение пользователя в DistKontrolUSB.

1. Назначение

DiskControl — это C++/Win32-утилита поверх штатного клиента DistKontrolUSB. Она показывает пользователю только разрешенные USB-токены, подключает и отключает их через локальный канал \\.\pipe\dkclient, а администратору дает удобный интерфейс для формирования файла доступа.

Ключевой проверенный вывод: чтобы в родном окне DistKontrolUSB занятый токен отображался не как СИСТЕМА, процесс dkcl64.exe должен быть запущен службой под пользовательской учетной записью. Мы это проверили вручную: после запуска службы под доменным пользователем DistKontrolUSB начал показывать логин пользователя.

PowerShell-скрипты в проекте сейчас остаются как установочные, диагностические и прототипные инструменты. Основной рабочий путь — C++ приложения:

  • DiskControl.exe — обычная пользовательская утилита.
  • DiskControl.Admin.exe — админская утилита для настройки доступа.
  • dkcl64.exe — штатный клиент DistKontrolUSB, установленный как служба dkclient.

2. Как это устроено

DiskControl.exe Пользователь видит текущего пользователя сверху, список разрешенных токенов, кнопки Обновить, Подключить, Отключить. Политика читается из allow.json.
DiskControl.Admin.exe Администратор видит все токены, ищет по endpoint/имени/продукту, отмечает галочками доступ для выбранного пользователя и сохраняет конфигурацию.
dkcl64.exe Штатный клиент DistKontrolUSB. В нашей схеме запускается как Windows-служба dkclient под учеткой пользователя установки.
allow.json Основной файл политики доступа. По умолчанию лежит в C:\ProgramData\DiskControl\allow.json. Пользователи читают, администраторы изменяют.

Поток работы

  1. Служба dkclient запускает dkcl64.exe -n --config="C:\Program Files\DiskControl\dkcl.ini".
  2. dkcl64.exe поднимает локальный канал \\.\pipe\dkclient.
  3. DiskControl.exe читает allow.json и показывает только разрешенные текущему Windows-пользователю токены.
  4. При подключении отправляется команда USE,<endpoint>, при отключении — STOP USING,<endpoint>.
  5. Родной DistKontrolUSB видит, что токен занят учеткой, под которой работает служба dkclient.

3. Установка

Обычный вариант для рабочего места — запустить установщик:

dist\DiskControl-Setup.exe

Установщик запрашивает права администратора через UAC, затем показывает учетную запись службы, пароль и папку общего состояния таймеров. По умолчанию в поле Account подставляется текущая учетная запись Windows. Ее можно оставить или заменить на нужный формат, например:

OSNOVA\a.nikitin
a.s.nikitin@osnova.local
Пароль нужен не DiskControl как приложению, а Windows Service Control Manager: без пароля Windows не создаст службу под обычной пользовательской учеткой. Установщик передает пароль в Windows при создании службы. В командную строку пароль не записывается.

В поле папки таймеров рекомендуется указать один UNC-путь для всех рабочих мест, например \\SERVER\DiskControlState. У пользователей должны быть права чтения, создания и изменения файлов в этой папке. Если поле оставить пустым, используется локальный C:\ProgramData\DiskControl\usage.json, и общий таймер между компьютерами работать не будет.

Что делает установщик

  • Копирует DiskControl.exe, DiskControl.Admin.exe, dkcl64.exe, dkcl.ini и документацию в C:\Program Files\DiskControl.
  • Создает C:\ProgramData\DiskControl, пустой безопасный allow.json и папку logs. Демонстрационный allowlist.example.json никогда не назначается как рабочая политика.
  • Создает или проверяет usage.json в выбранной локальной либо общей сетевой папке и записывает его путь в allow.json.
  • Настраивает ACL: обычным пользователям чтение/запуск клиентской части, администраторам изменение.
  • Отдельно ограничивает запуск dkcl64.exe: SYSTEM и администраторы получают полный доступ, выбранная учетная запись службы получает чтение/запуск, группа Users не получает общий запуск этого EXE.
  • Выдает выбранной учетной записи право Log on as a service.
  • Создает службу dkclient под выбранной учетной записью.
  • Запускает службу, если не указан режим -NoStartService.
  • Создает ярлыки в меню Пуск и ярлык DiskControl на общем рабочем столе.
  • Регистрирует удаление через Windows “Программы и компоненты”.

Ручная установка из консоли

Если нужен запасной путь без графического EXE, можно открыть PowerShell/Command Prompt от администратора и выполнить:

install.cmd

Скрипт спросит пароль для учетной записи службы. Дополнительные варианты:

install.cmd -NoStartService
install.cmd -NoDesktopShortcut
install.cmd -SkipBuild

4. Почему служба должна работать под пользователем

Мы проверили поведение DistKontrolUSB: кто запускает dkcl64.exe, тот и отображается как владелец занятого токена. Если dkcl64.exe работает как LocalSystem, родной клиент на других компьютерах показывает СИСТЕМА. Если служба работает под OSNOVA\a.nikitin или UPN-учеткой, отображается логин пользователя.

Как запущен dkcl64.exe Что увидит DistKontrolUSB Вывод
LocalSystem СИСТЕМА Не подходит для понятного учета занятости.
Пользовательская учетная запись Логин пользователя Нужный режим для рабочих мест.

Проверка

sc.exe qc dkclient
sc.exe query dkclient

В sc.exe qc dkclient важны поля:

  • SERVICE_START_NAME — должна быть пользовательская учетная запись, не LocalSystem.
  • BINARY_PATH_NAME — должен указывать на C:\Program Files\DiskControl\dkcl64.exe с параметром --config.
Если на одном компьютере работают разные люди по очереди, служба все равно стартует под одной выбранной учеткой. Для динамической смены пользователя нужен отдельный следующий этап: брокер/служба DiskControl, которая умеет запускать клиент в пользовательской сессии или официально менять clientId, если это поддерживается API производителя.
Ограничение запуска dkcl64.exe снимает общий доступ группы Users, но выбранная учетная запись службы все равно получает право чтения/запуска. Если эта учетная запись совпадает с интерактивным пользователем, технически именно этот пользователь также сможет запустить файл напрямую. Для строгого запрета нужен отдельный сервисный аккаунт или следующий этап с защищающей службой.

5. Пользовательская утилита

DiskControl.exe запускается обычным пользователем. Вверху показывается текущий Windows-пользователь. Ниже отображается дерево токенов в стиле DistKontrolUSB: сначала группа ...-Gr-XX, внутри разрешенные пользователю токены из allow.json.

Действие Назначение
Обновить Перечитать список токенов из dkclient и заново применить политику.
Двойной клик по свободному токену Перед подключением еще раз проверяет токен по политике и отправляет USE,<endpoint>.
Двойной клик по токену, подключенному вами Отправляет STOP USING,<endpoint>, обновляет локальное состояние использования и перечитывает список.
Двойной клик по токену, занятому другим пользователем Не отключает чужой токен, а показывает в строке статуса, кем он занят.

При сворачивании окно остаётся на панели задач: режим трея отключён. При закрытии программы все токены, подключённые текущим пользователем через клиент, автоматически освобождаются.

Для каждого подключённого токена отображается обратный таймер 20 минут. После его окончания появляется вопрос о продолжении. Ответ «Да» запускает следующие 20 минут, ответ «Нет» освобождает токен. Если ответа нет одну минуту, токен освобождается автоматически.

6. Админская утилита

DiskControl.Admin.exe запускается с правами администратора. Она нужна для формирования и редактирования allow.json.

Основной сценарий

  1. Запустить DiskControl Admin.
  2. В поле Пользователь указать логин, например OSNOVA\a.nikitin.
  3. Нажать Обновить, чтобы увидеть слева разрешённые токены, а справа токены, которые можно добавить.
  4. Двойным кликом перенести нужные токены из правой части в левую. Двойной клик по токену слева убирает его из доступа.
  5. Нажать Сохранить доступ.

Левая часть окна становится списком allowedDevices выбранного пользователя. Перемещение между частями меняет только подготовленный список; запись в файл выполняется кнопкой Сохранить доступ.

Поиск

Поле Поиск фильтрует список по:

  • Endpoint, например distkontrolusb64-1-Gr-01.1124;
  • имени токена, например ИНТЕГРАЛ;
  • продукту, например Rutoken lite.

Открытие другого конфига

Кнопка Открыть конфиг позволяет выбрать другой JSON-файл. Если внутри некорректный JSON, админка заменяет его на пустой валидный allow.json, а старое содержимое сохраняет рядом как *.invalid-*.bak.

Сортировка

Клик по заголовку столбца сортирует таблицу по этому столбцу. Повторный клик меняет направление сортировки.

Экспорт CSV/JSON

Экспорт — это не файл настройки доступа. Это выгрузка текущего списка для сверки, Excel, отправки в поддержку или сравнения состояний. Конфигурацией доступа остается allow.json, который формируется кнопкой Сохранить доступ.

7. Файл allow.json

Основной файл политики лежит здесь:

C:\ProgramData\DiskControl\allow.json

Пример структуры:

{
  "pipeName": "dkclient",
  "refreshSeconds": 5,
  "usageStatePath": "C:\\ProgramData\\DiskControl\\usage.json",
  "userAssignments": [
    {
      "users": [
        "OSNOVA\\a.nikitin"
      ],
      "groups": [],
      "allowedDevices": [
        {
          "endpoint": "distkontrolusb64-1-Gr-01.1124",
          "nickname": "ИНТЕГРАЛ УК ООО",
          "product": "Rutoken lite"
        }
      ]
    }
  ]
}
Поле Что означает
pipeName Имя локального канала DistKontrolUSB. Сейчас используется dkclient.
refreshSeconds Период автообновления, если используется в интерфейсе.
usageStatePath Единственный источник начала 20-минутного интервала и владельца токена для всех экземпляров DiskControl. Для общей работы на разных компьютерах здесь должен быть один и тот же UNC-путь.
userAssignments Список назначений: пользователи/группы и разрешенные им токены.
users Логины Windows: DOMAIN\user, короткое имя или SID.
groups Группы Windows. Можно оставить пустым массивом.
allowedDevices Токены, которые пользователь увидит и сможет подключать через DiskControl.
endpoint Главный идентификатор токена из DistKontrolUSB.
nickname Имя токена. Если заполнено, используется как дополнительная проверка.
product Продукт, например Rutoken lite. Если заполнено, тоже проверяется.
Поля clientExecutable больше нет в плане и в новой политике. Путь к dkcl64.exe находится в настройке службы Windows, а не в allow.json.

8. Где лежат файлы

Путь Назначение
C:\Program Files\DiskControl\DiskControl.exe Пользовательская утилита.
C:\Program Files\DiskControl\DiskControl.Admin.exe Админская утилита.
C:\Program Files\DiskControl\dkcl64.exe Штатный клиент DistKontrolUSB, запускается службой dkclient. Запуск ограничен ACL: не для всей группы Users, а для администраторов, SYSTEM и учетной записи службы.
C:\Program Files\DiskControl\dkcl.ini Конфиг штатного клиента dkcl64.exe. Наша политика доступа хранится отдельно.
C:\ProgramData\DiskControl\allow.json Основной файл доступа.
usage.json по пути из usageStatePath Общее состояние владельцев и таймеров. Может находиться в C:\ProgramData\DiskControl или в общей сетевой папке.
C:\ProgramData\DiskControl\logs Логи запуска, действий, установки и диагностики.

9. Диагностика

Отдельная диагностическая утилита больше не добавляется при установке. Для проверки состояния используем логи DiskControl и стандартные команды Windows.

Быстрая ручная проверка:

sc.exe query dkclient
sc.exe qc dkclient
dir C:\ProgramData\DiskControl\logs

Если DistKontrolUSB снова показывает “СИСТЕМА”

  1. Проверить sc.exe qc dkclient.
  2. Убедиться, что SERVICE_START_NAME не LocalSystem, а нужный пользователь.
  3. Остановить старые процессы dkcl64.exe, если они запущены не от службы.
  4. Перезапустить службу dkclient.

Если служба не запускается

  • Проверить пароль учетной записи службы.
  • Проверить, не заблокирована ли учетная запись и не истек ли пароль.
  • Проверить право Log on as a service.
  • Проверить, что путь к dkcl64.exe и dkcl.ini существует.

Если админка или пользовательская утилита сразу закрывается

  • Открыть C:\ProgramData\DiskControl\logs.
  • Найти свежий startup-YYYYMMDD.log.
  • Проверить, не запускается ли старый EXE из старой папки.
  • Проверить, не блокирует ли запуск антивирус/AppLocker/SmartScreen.

build-installer.cmd -CertificatePath "C:\Certs\company-code-signing.pfx" -CertificatePassword "PASSWORD"

11. Удаление

Удалить DiskControl можно через Windows “Приложения”, через ярлык Uninstall DiskControl в меню Пуск или командой:

uninstall.cmd

По умолчанию папка C:\ProgramData\DiskControl сохраняется, чтобы не потерять allow.json и логи. Если нужно удалить и данные:

uninstall.cmd -RemoveData

12. Текущие ограничения и следующий этап

  • allow.json ограничивает поведение нашей утилиты DiskControl. Для строгой защиты от обхода через сторонние инструменты нужны дополнительные меры Windows: права на запуск, AppLocker/WDAC, скрытие штатного GUI или отдельная защищающая служба.
  • Служба dkclient работает под одной учетной записью. Это хорошо для рабочего места, закрепленного за пользователем. Для терминального сценария с несколькими пользователями нужна отдельная архитектура.
  • usage.json помогает нашей утилите показывать владельца, но родной DistKontrolUSB ориентируется на учетку процесса dkcl64.exe.
  • Установщик без подписи может предупреждаться SmartScreen.

Что делать дальше

  1. Проверить новый установщик на тестовом компьютере.
  2. Убедиться, что служба создалась под нужным пользователем и DistKontrolUSB показывает логин.
  3. Проверить сценарий админки: поиск, галочки, сохранение доступа, повторное открытие allow.json.
  4. После стабилизации решить вопрос строгой защиты от обхода и подписи установщика.

# MSI-пакет клиента DistControl

## Готовая конфигурация

По умолчанию пакет собирается со значениями:

- сервер управления: `http://10.14.32.179:8765`;
- папка таймеров: `\\dfs\fs\IT\soft\DistKontrol\time`.

MSI запускает тот же установщик DistControl, который определяет пользователя
активного сеанса или явно переданный SID и устанавливает программу в его профиль.
Для каждого пользователя создаются своя политика, журналы, служба
`DistControlAgent-<SID>` и запись удаления. Системная USB-служба `dkclient`
использует `%ProgramFiles%\DistControl Runtime`, общие маршруты хранятся в
`%ProgramData%\DistControl\Runtime`. Следующая установка сохраняет предыдущую.
Вложенный установщик кэшируется в `C:\Program Files\DistControl Installer`,
а установка выполняется в повышенной системной части Windows Installer без скрытого
интерактивного окна. Если установка не завершилась, MSI откатывается и его можно запустить
повторно. MSI остаётся машинной оболочкой для GPO и скрыт из списка приложений;
в списке приложений пользователь видит собственную запись DistControl.

Для ручной установки запустите MSI из сеанса целевого пользователя. Пакет также поддерживает
скрытую установку в активном сеансе пользователя, в том числе через политику:

```powershell
msiexec.exe /i .\DistControl-Client-0.8.20.msi
```

Скрытая установка:

```powershell
msiexec.exe /i .\DistControl-Client-0.8.20.msi /qn /norestart
```

Для конкретного сотрудника, в том числе при запуске от SYSTEM или другого администратора:

```powershell
msiexec.exe /i .\DistControl-Client-0.8.20.msi /qn /norestart DISTCONTROLTARGETUSERSID=S-1-5-21-111-222-333-1001
```

Повторный `/i` создаёт или обновляет клиент указанного пользователя, даже если
общая оболочка MSI уже установлена. Свойство `DISTCONTROLENSUREUSER=1` пропускает
уже установленных пользователей; последующие обновления доставляет их агент.

## Удаление пользователя и полного комплекта

Запись DistControl в «Программах и компонентах» и ярлык «Удалить» в меню Пуск
удаляют только выбранного пользователя. Его агент удаляется, остальные установки,
USB-служба и маршруты сохраняются. Общие компоненты и регистрация MSI удаляются
после последнего пользователя. Драйвер сохраняется.

Команда `/x` для общей MSI-оболочки удаляет **все зарегистрированные пользовательские клиенты**:

```powershell
msiexec.exe /x .\DistControl-Client-0.8.20.msi /qn /norestart /l*v C:\Windows\Temp\DistControl-uninstall.log
```

Удаление последнего пользователя через `Uninstall-DistControl.exe` снимает
регистрацию MSI-продуктов с UpgradeCode
`{8E2503E8-7098-4FF1-9278-7AC5C473E0CF}`. Защита от повторного вызова не даёт
цепочке `EXE -> msiexec -> MSI custom action` запустить удаление второй раз.
Папка данных `%LOCALAPPDATA%\DistControl` по умолчанию сохраняется для журналов
и резервной политики; вариант «удалить данные» доступен штатному EXE-удалятору.

В 0.8.20 MSI запускает текущий удалятор и скрипты из временного каталога, даже
если установленный удалятор отсутствует или устарел. При обычном запуске исходный
EXE завершает работу до удаления его каталога, устраняя блокировку файла.
Дополнительные журналы: `%ProgramData%\DistControl\logs\msi-uninstall.log` и
`%ProgramData%\DistControl\logs\uninstall-bootstrap.log`.

Для уже установленной версии с ошибкой распакуйте новый `DistControl-Installer.zip`
и запустите `repair-uninstall.cmd`. Для явного выбора пользователя:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Repair-Uninstall-DistControl.ps1 -TargetUserSid S-1-5-21-111-222-333-1001
```

## Сборка с другими адресами

Исходный код редактировать не требуется. Запустите из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installer\Build-MsiPackage.ps1 `
  -DefaultServerUrl "http://10.14.32.200:8765" `
  -DefaultUsageStateDirectory "\\NEW-SERVER\DistControl\time"
```

Результат появится в `dist`:

- `DistControl-Client-0.8.20.msi`;
- `DistControl-Client-0.8.20.msi.sha256`.

WiX Toolset загружается автоматически в `build\tools` и не устанавливается в
Windows. Для сборки без повторной компиляции приложения добавьте `-SkipBuild`.

## Комплект для доменной GPO

Для развёртывания выбранным пользователям соберите отдельный комплект:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installer\Build-GpoMsiPackage.ps1
```

Результат находится в `dist\GPO`. Для доменного развёртывания создайте в
**Конфигурации пользователя** задачу планировщика, которая запускается от
`SYSTEM` через 30 секунд после входа и выполняет MSI в тихом режиме. Такая схема
не задерживает вход в Windows. У каждого пользователя своя задача с SID,
подставленным GPP через `%LogonUserSid%`; это исключает выбор другого активного
сеанса. Точные параметры задачи записываются в `dist\GPO\README-GPO.txt`.

Не назначайте один и тот же MSI одновременно через раздел «Установка программ»
и через планировщик. Синхронная политика «Всегда ждать сеть при запуске
компьютера и входе в систему» для фоновой установки не требуется.

Для MSI адреса зашиваются при сборке. В отдельном `DistControl-Setup.exe` их можно
проверить или временно изменить в окне перед установкой.

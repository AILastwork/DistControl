# DistControl

Текущая версия: 0.6.0. Приложение и установочные каталоги переименованы в
`DistControl`. При обновлении установщик переносит существующую политику и
журналы из `C:\ProgramData\DiskControl` в `%LOCALAPPDATA%\DistControl`.
Исходные данные в `ProgramData` сохраняются как резерв для отката, а старая
папка `C:\Program Files\DiskControl` удаляется после запуска новой службы.
Программа устанавливается только для выбранной учетной записи Windows:
исполняемые файлы находятся в `%LOCALAPPDATA%\Programs\DistControl`, а политика,
состояние и журналы — в `%LOCALAPPDATA%\DistControl` этого пользователя.
При переключении токена приложение сначала подтверждённо
освобождает ранее подключённый токен с другим VPN-профилем, а затем меняет VPN.
Ход подключения и отключения показывается по понятным этапам и в процентах.
Успешное событие `USE` содержит проверенный внешний IP. Журналы хранятся 30 дней,
общий размер папки ограничен примерно 100 МБ, отдельного файла — 20 МБ.

Админская утилита сохраняет только явно добавленные и удалённые разрешения,
не удаляя токены, временно отсутствующие в выдаче службы. Конфигурация защищена
от одновременной перезаписи двумя администраторами. Несохранённые изменения
помечаются в заголовке, а VPN можно назначать сразу нескольким токенам.

## Готовая сборка

Актуальный установщик после сборки находится в `dist\DistControl-Setup.exe`,
переносимый пакет — в `dist\DistControl-Installer.zip`.

Готовая версия `0.6.0` для скачивания с GitHub:
[DistControl-0.6.0-win64.zip](release-assets/DistControl-0.6.0-win64.zip).
Контрольная сумма архива:
[DistControl-0.6.0-win64.zip.sha256](release-assets/DistControl-0.6.0-win64.zip.sha256).

`DistControl` — небольшая программа для Windows, которая показывает и
подключает только разрешённые USB-ключи через клиент `DistKontrolUSB`.

Программа использует тот же локальный именованный канал и те же команды,
что и пример `DKCLHelper` от производителя:

- `LIST` — получить список устройств;
- `DEVICE INFO,<адрес>` — получить сведения об устройстве;
- `USE,<адрес>` — подключить устройство;
- `STOP USING,<адрес>` — отключить устройство.

Разрешённые устройства задаются в файле политики `allow.json`.

## Модель разграничения

Количество групп концентратора не используется для разграничения. В одном
файле политики можно назначить любое число USB-ключей любому числу
пользователей Windows:

- пользователь определяется по `DOMAIN\имя`, короткому имени или SID;
- поддерживаются локальные и доменные группы Windows;
- один ключ можно назначить нескольким пользователям;
- одному пользователю можно назначить ключи из разных групп концентратора;
- пользователь без назначения не видит ни одного ключа.

Каждому USB-ключу следует присвоить уникальное имя, например `BANK-KEY-01`,
и определить его адрес вида `OFFICE-HUB-Gr-1.3`.

## Настройка программы

Откройте `allow.json` и заполните параметры:

```json
{
  "pipeName": "dkclient",
  "refreshSeconds": 5,
  "vpnProfiles": [
    {
      "id": "direct-office",
      "mode": "direct",
      "enabled": true
    }
  ],
  "userAssignments": [
    {
      "users": ["DOMAIN\\ivanov", "ivanov"],
      "groups": [],
      "allowedDevices": [
        {
          "endpoint": "OFFICE-HUB-Gr-1.3",
          "nickname": "BANK-KEY-01",
          "product": "Rutoken",
          "vpnProfile": "direct-office"
        },
        {
          "endpoint": "OFFICE-HUB-Gr-4.8",
          "nickname": "BANK-KEY-32",
          "product": "Rutoken",
          "vpnProfile": "direct-office"
        }
      ]
    },
    {
      "users": [],
      "groups": ["DOMAIN\\Бухгалтерия"],
      "allowedDevices": [
        {
          "endpoint": "OFFICE-HUB-Gr-6.4",
          "nickname": "REPORT-KEY-01",
          "product": "",
          "vpnProfile": "direct-office"
        }
      ]
    }
  ]
}
```

Назначение полей:

- `pipeName` — имя локального канала клиента, обычно `dkclient`;
- `refreshSeconds` — период обновления списка в секундах;
- `vpnProfiles` — разрешённые сетевые режимы: существующий профиль VPN Windows
  (`mode: windowsVpn`) или прямое подключение без VPN (`mode: direct`). Админка
  создаёт технический `id` автоматически, вручную вводить его не требуется;
- `userAssignments` — назначения устройств пользователям и группам;
- `users` — имена пользователей Windows или SID;
- `groups` — локальные или доменные группы Windows;
- `allowedDevices` — устройства для конкретного назначения;
- `endpoint` — обязательный адрес устройства в DistKontrol;
- `nickname` — дополнительная проверка имени устройства;
- `product` — дополнительная проверка названия продукта.
- `vpnProfile` — обязательная для подключения ссылка на сетевой режим из
  `vpnProfiles`; без неё токен отображается, но подключение запрещено.

Если проверять `nickname` или `product` не требуется, укажите пустую строку.

## Запуск

Соберите Release-версию:

```powershell
build-vs.cmd Release
```

Запустите пользовательскую утилиту:

```powershell
build\x64\Release\DistControl.exe
```

При сворачивании приложение остаётся на панели задач. Режим трея отключён.
При закрытии пользовательской утилиты она пытается освободить все токены,
подключённые текущим пользователем.

Программа подключается к каналу `\\.\pipe\dkclient`. Перед запуском интерфейса
клиент `dkcl64.exe` должен быть поднят установщиком как служба Windows.

В окне будут доступны действия:

- **Обновить** — перечитать список устройств; во время операции отображаются полоса прогресса, проценты и число обработанных токенов;
- **Подключить** — отправить команду `USE`;
- **Отключить** — отправить команду `STOP USING`.

Перед подключением программа повторно получает сведения об устройстве и
проверяет его по белому списку. Для каждого токена обязательно назначается
существующий профиль VPN Windows либо режим «Без VPN».
DistControl проверяет отсутствие активного токена на другом сетевом режиме,
отключает все активные VPN Windows, подключает требуемый профиль при его наличии
и проверяет сохранность локальной сети. Команда `USE` отправляется только после успешного
завершения всех проверок.

При отключении сначала подтверждается, что токен принадлежит текущему
пользователю, затем отправляется `STOP USING`. После успешного ответа удаляется
запись таймера. VPN отключается, только если ни один другой активный токен
текущего пользователя не использует этот же профиль. Ошибка проверки состояния
VPN не отменяет уже выполненное освобождение токена и записывается в журнал.

Для подключённого токена действует 20-минутный интервал. После него программа
предлагает продолжить работу; при отказе или отсутствии ответа в течение минуты
токен освобождается. Для одинакового таймера на всех компьютерах при установке
укажите одну общую сетевую папку для `usage.json`.

## Установка и служба

Обычный вариант для пользователя — запустить Windows-установщик:

```powershell
dist\DistControl-Setup.exe
```

При запуске он запросит права администратора через UAC, затем предложит выбрать
учетную запись Windows и выполнит установку только в ее профиль. Это работает и
тогда, когда UAC подтверждает другой администратор: установщик определяет SID и
путь профиля именно по учетной записи, указанной в окне установки.

- копирует `DistControl.exe`, `DistControl.Admin.exe`, `dkcl64.exe` и `dkcl.ini`
  в `%LOCALAPPDATA%\Programs\DistControl` выбранного пользователя;
- создаёт в его профиле `%LOCALAPPDATA%\DistControl\allow.json`, папки `logs` и
  `state`; другой пользователь не получает отдельную политику автоматически;
- настраивает ACL: выбранная учетная запись читает `allow.json`, но не изменяет
  его; каталоги `logs` и `state` доступны ей для работы клиента;
- подготавливает `%APPDATA%\dkcl.ini` и `%APPDATA%\dkcl64.ini`, которые штатный
  клиент обычно создаёт при первом интерактивном запуске;
- регистрирует `dkcl64.exe` как службу Windows `dkclient`, включает SID службы и
  закрывает ручной запуск `dkcl64.exe` и чтение `dkcl.ini` обычным пользователем;
- запускает службу и проверяет не только состояние `Running`, но и реальный ответ
  списка токенов по каналу `dkclient`; вручную запускать `dkcl64.exe` до установки
  больше не требуется;
- создаёт ярлыки только в меню Пуск и на рабочем столе выбранного пользователя;
- регистрирует DistControl в списке установленных приложений только для него;
- читает адреса `ManualHubs` из `dkcl.ini` и создаёт для них постоянные
  маршруты `/32` через физический LAN/Wi-Fi-шлюз. Это сохраняет связь службы
  `dkclient` с USB-хабами при включении полного VPN-туннеля. При удалении
  DistControl удаляются только маршруты, записанные установщиком в
  `%LOCALAPPDATA%\DistControl\managed-hub-routes.json`.

Установщик не создаёт и не изменяет VPN-профили Windows. На новой установке
`vpnProfiles` пуст. Нужные подключения заранее создаются штатными средствами
Windows, после чего администратор считывает их в `DistControl.Admin.exe` и
назначает токенам. Разрешённые внешние IP не настраиваются: приложение проверяет
сам факт подключения выбранного VPN и доступность локальной сети. Фактический
внешний IP записывается в журнал только для диагностики. Общие ключи L2TP
остаются только в настройках Windows и не передаются DistControl.
Установщик не отключает и не изменяет сторонние VPN-клиенты, включая Amnezia.

Служба `dkclient` является системной и остаётся общей для компьютера, поэтому UAC
и пароль выбранной учетной записи по-прежнему нужны. На одном компьютере может
работать только один экземпляр этой службы. Если запустить установку для другой
учетной записи, служба будет пересоздана под ней, чтобы сервер токенов показывал
актуального владельца.

Запасной ручной запуск установки из консоли администратора:

```powershell
install.cmd
```

Полезные варианты:

```powershell
install.cmd -SkipBuild
install.cmd -NoStartService
install.cmd -NoDesktopShortcut
```

Сформировать установщик и переносимый zip-пакет:

```powershell
build-installer.cmd
```

Результаты будут лежать здесь:

```powershell
dist\DistControl-Setup.exe
dist\DistControl-Installer.zip
```

Удаление приложения и службы доступно через:

- **Параметры Windows → Приложения** или **Программы и компоненты**;
- ярлык **Uninstall DistControl** в меню Пуск;
- ручной скрипт:

```powershell
uninstall.cmd
```

Чтобы удалить ещё и `%LOCALAPPDATA%\DistControl` с политикой и логами:

```powershell
uninstall.cmd -RemoveData
```

`dkcl.ini` нужен штатному клиенту `dkcl64.exe` при запуске как службы.
Наше разграничение доступа хранится отдельно в `allow.json`.

## SmartScreen и подпись

Если Windows показывает “Система Windows защитила ваш компьютер”, это означает,
что `DistControl-Setup.exe` не подписан доверенным издателем или ещё не имеет
репутации у Microsoft SmartScreen.

Для теста можно нажать **Подробнее → Выполнить**, но для нормального
распространения нужно подписать EXE сертификатом подписи кода организации.
Сборка уже поддерживает подпись:

```powershell
build-installer.cmd -CertificateThumbprint "THUMBPRINT"
```

или PFX-файлом:

```powershell
build-installer.cmd -CertificatePath "C:\Certs\company-code-signing.pfx" -CertificatePassword "PASSWORD"
```

Лучший вариант против SmartScreen — EV Code Signing или Microsoft Trusted
Signing. Обычный OV-сертификат тоже покажет издателя, но репутация может
набираться постепенно.

## Если админка закрывается сразу

Для компьютеров без Visual Studio Release-сборка собирается со статическим MSVC
runtime, поэтому отдельный VC++ Redistributable обычно не нужен. Если
`DistControl.Admin.exe` всё равно закрывается сразу:

1. Используйте свежий `dist\DistControl-Installer.zip`.
2. Запустите `diagnose.cmd` на проблемном компьютере.
3. Проверьте свежий лог:

```powershell
%LOCALAPPDATA%\DistControl\logs\startup-YYYYMMDD.log
```

Если такого файла нет вообще, приложение может быть заблокировано антивирусом,
AppLocker/политикой запуска или запущено из старого пакета.

## Пошаговая диагностика подключения токена

При каждом запуске, обновлении списка, подключении и отключении DistControl пишет
понятный журнал на русском языке:

```powershell
%LOCALAPPDATA%\DistControl\logs\trace-YYYYMMDD.log
```

Каждая операция получает собственный номер, например `CONNECT-1234-000007`.
По нему видны все этапы одной попытки и их длительность: проверка политики,
подключение VPN, запись внешнего IP для диагностики, восстановление каталога DistKontrolUSB,
команды `DEVICE INFO`, `USE` или `STOP USING` и обновление интерфейса. Пароли и
общие ключи VPN в журнал не записываются.

Для разбора сбоя воспроизведите его один раз и передайте администратору свежие
`trace-YYYYMMDD.log`, `audit-YYYYMMDD.csv` и `startup-YYYYMMDD.log` из этой папки.

## Администрирование allow.json

В C++-версии теперь две отдельные утилиты:

- `DistControl.exe` — пользовательская утилита. Только читает политику и
  позволяет подключать/отключать разрешённые токены.
- `DistControl.Admin.exe` — админская утилита. Показывает полный список,
  ищет токены, открывает файл политики и сохраняет подготовленные изменения
  доступа пользователя.

В таблицах админки основные столбцы идут в порядке `Endpoint`, `Имя`, `VPN`,
`Состояние`, `Кем занят`, `Адрес`, `Осталось`, `Продукт`. При назначении VPN
админка показывает уже существующие подключения Windows выбранного пользователя
и общесистемные подключения. При работе с удалённым компьютером через `C$`
читаются его телефонные книги RAS и свежий отчёт клиента, а изменяется только
его `allow.json`.

Клиент раз в 30 секунд записывает текущий внешний IP и список активных VPN
Windows в `%LOCALAPPDATA%\DistControl\state\network-state.json`. Админка использует
свежий отчёт для отображения состояния сети и диагностики.

Без параметров обе утилиты используют основной файл политики:

```powershell
%LOCALAPPDATA%\DistControl\allow.json
```

При необходимости путь можно переопределить явно:

```powershell
DistControl.exe --policy "D:\Configs\allow.json"
DistControl.Admin.exe --policy "D:\Configs\allow.json"
```

Локальные `allow.json` и `allowlist.json` больше не подхватываются
автоматически. Их можно использовать только через `--policy` или кнопку
**Открыть конфиг** в админской утилите.

Если в админской утилите открыт битый или структурно некорректный JSON,
`DistControl.Admin.exe` показывает ошибку и не изменяет файл. Это исключает
автоматическую замену рабочей политики пустой конфигурацией.

Чтобы сформировать доступ пользователя:

1. Откройте `build\x64\Release\DistControl.Admin.exe`.
2. При необходимости нажмите **Открыть конфиг** и выберите нужный `allow.json`.
3. В поле **Пользователь** введите имя в формате `DOMAIN\user` или `user`.
4. Дождитесь полного списка токенов.
5. Найдите нужные токены через **Поиск** по `Endpoint`, имени, продукту, VPN,
   состоянию, владельцу или адресу.
6. Перенесите нужные токены в левый список кнопкой **Добавить**, а лишние
   уберите из него кнопкой **Убрать**.
7. Нажмите **Сохранить доступ**.

После этого админская утилита обновит файл политики:

- для существующего блока будут записаны только явно добавленные и удалённые
  токены; отсутствующие в текущей выдаче службы записи сохраняются;
- если блока нет, будет создан новый элемент в `userAssignments`;
- короткое имя `user` совпадает с существующим блоком `DOMAIN\user`.

Левый список показывает разрешённые токены выбранного пользователя, правый —
доступные для добавления. Клик по заголовку столбца сортирует таблицу. До
успешной загрузки пользователя сохранение заблокировано. Несохранённое
состояние отмечается в заголовке; при смене пользователя, компьютера,
конфига или закрытии программа запрашивает подтверждение.

Перед записью проверяется ревизия `allow.json`. Если другой администратор уже
изменил этот файл, текущее сохранение останавливается и предлагает обновить
данные. Для массового назначения VPN выделите несколько разрешённых токенов,
нажмите **VPN для токена** и выберите профиль Windows. Список профилей
поддерживает ввод по первым буквам.

Экспорт **CSV** нужен для Excel, сверки и инвентаризации. Экспорт **JSON** нужен
для технической диагностики, сравнения выгрузок и дальнейшей обработки
скриптами. Экспортируется текущий вид таблицы, включая применённый поиск.

## Проверка без графического интерфейса

## Ограничения безопасности

Оборудование не обеспечивает требуемую матрицу доступа, поэтому проверка
выполняется на компьютере пользователя. Текущая версия является клиентским
контроллером, а не неотключаемой системой защиты.

Установщик включает уникальный SID `NT SERVICE\dkclient`. Файлы `dkcl64.exe` и
`dkcl.ini` доступны процессу, запущенному диспетчером служб, но недоступны той же
пользовательской учётной записи при обычном ручном запуске. Поэтому имя владельца
токена в DistKontrolUSB остаётся реальным именем пользователя.

`allow.json` находится в профиле пользователя, но наследование прав отключено:
обычные пользователи читают политику, администраторы и `SYSTEM` изменяют её.
Изменяемые клиентом файлы находятся отдельно в каталогах `logs` и `state`.

Локальный администратор по-прежнему способен изменить ACL, заменить файлы или
перенастроить службу. Полностью закрыть приложение от администратора Windows
невозможно.

## Результаты анализа исходника производителя

- `DKCLHelper` работает через `\\.\pipe\dkclient` и сам не реализует
  USB-over-IP.
- Команда `LIST` возвращает адреса устройств вида `SERVER-Gr-N.PORT`.
- Из ответа `DEVICE INFO` пример извлекает только `NICKNAME`, `IN USE BY`
  и `PRODUCT`.
- Серийный номер USB, `VID` и `PID` опубликованный пример не предоставляет.
- Штатный пример показывает все устройства из `LIST` и не проверяет белый
  список перед командой `USE`.
- В примере производителя указатель на локальный объект `IPCClient`
  передаётся периодическому таймеру GTK. После завершения обработчика этот
  указатель может стать недействительным. В `DistControl` для каждой команды
  создаётся отдельное подключение к каналу.

Таким образом, доступная идентификация ключа выполняется по адресу
`endpoint`, а также, при необходимости, по `nickname` и `product`.

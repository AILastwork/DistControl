# DiskControl

`DiskControl` — небольшая программа для Windows, которая показывает и
подключает только разрешённые USB-ключи через клиент `DistKontrolUSB`.

Программа использует тот же локальный именованный канал и те же команды,
что и пример `DKCLHelper` от производителя:

- `LIST` — получить список устройств;
- `DEVICE INFO,<адрес>` — получить сведения об устройстве;
- `USE,<адрес>` — подключить устройство;
- `STOP USING,<адрес>` — отключить устройство.

Разрешённые устройства задаются в файле политики `allow.json`.

## Состав

- `DiskControl.sln` — Visual Studio solution для C++/Win32 версии;
- `src\DiskControl` — пользовательская утилита `DiskControl.exe`;
- `src\DiskControl.Admin` — админская утилита `DiskControl.Admin.exe`;
- `src\DiskControl.Tests` — консольные тесты парсинга, политики и CSV-логики;
- `build-vs.cmd` — сборка через MSBuild;
- `test-vs.cmd` — сборка Debug и запуск `DiskControl.Tests.exe`;
- `install.cmd` — установка приложения, ACL и службы `dkclient` от имени администратора;
- `uninstall.cmd` — удаление приложения и службы;
- `diagnose.cmd` — проверка службы, политики, файлов и логов на рабочем месте;
- `build-installer.cmd` — сборка `DiskControl-Setup.exe` и переносимого zip-пакета;
- `C:\ProgramData\DiskControl\allow.json` — основной файл политики доступа;
- `allowlist.json` — локальный пример/старый файл для ручной разработки через `--policy`;
- `assets\diskcontrol-icon.png` — исходный PNG-значок программы;
- `DiskControl.ps1` и `Run-DiskControl.cmd` — PowerShell-прототип и диагностика;
- `vendor-source` — исходный код примера производителя.

## Модель разграничения

Количество групп концентратора не используется для разграничения. В одном
файле политики можно назначить любое число USB-ключей любому числу
пользователей Windows:

- пользователь определяется по `DOMAIN\имя`, короткому имени или SID;
- поддерживаются локальные и доменные группы Windows;
- один ключ можно назначить нескольким пользователям;
- одному пользователю можно назначить ключи из разных групп концентратора;
- пользователь без назначения не видит ни одного ключа.

Каждому USB-ключу следует присвоить уникальное имя, например `BANK-KEY-01`,
и определить его адрес вида `OFFICE-HUB-Gr-1.3`.

## Настройка программы

Откройте `allow.json` и заполните параметры:

```json
{
  "pipeName": "dkclient",
  "refreshSeconds": 5,
  "userAssignments": [
    {
      "users": ["DOMAIN\\ivanov", "ivanov"],
      "groups": [],
      "allowedDevices": [
        {
          "endpoint": "OFFICE-HUB-Gr-1.3",
          "nickname": "BANK-KEY-01",
          "product": "Rutoken"
        },
        {
          "endpoint": "OFFICE-HUB-Gr-4.8",
          "nickname": "BANK-KEY-32",
          "product": "Rutoken"
        }
      ]
    },
    {
      "users": [],
      "groups": ["DOMAIN\\Бухгалтерия"],
      "allowedDevices": [
        {
          "endpoint": "OFFICE-HUB-Gr-6.4",
          "nickname": "REPORT-KEY-01",
          "product": ""
        }
      ]
    }
  ]
}
```

Назначение полей:

- `pipeName` — имя локального канала клиента, обычно `dkclient`;
- `refreshSeconds` — период обновления списка в секундах;
- `userAssignments` — назначения устройств пользователям и группам;
- `users` — имена пользователей Windows или SID;
- `groups` — локальные или доменные группы Windows;
- `allowedDevices` — устройства для конкретного назначения;
- `endpoint` — обязательный адрес устройства в DistKontrol;
- `nickname` — дополнительная проверка имени устройства;
- `product` — дополнительная проверка названия продукта.

Если проверять `nickname` или `product` не требуется, укажите пустую строку.

## Запуск

Соберите Release-версию:

```powershell
build-vs.cmd Release
```

Запустите пользовательскую утилиту:

```powershell
build\x64\Release\DiskControl.exe
```

При сворачивании приложение остаётся на панели задач. Режим трея отключён.
При закрытии пользовательской утилиты она пытается освободить все токены,
подключённые текущим пользователем.

Программа подключается к каналу `\\.\pipe\dkclient`. Перед запуском интерфейса
клиент `dkcl64.exe` должен быть поднят установщиком как служба Windows.

В окне будут доступны действия:

- **Обновить** — перечитать список устройств;
- **Подключить** — отправить команду `USE`;
- **Отключить** — отправить команду `STOP USING`.

Перед подключением программа повторно получает сведения об устройстве и
проверяет его по белому списку.

Для подключённого токена действует 20-минутный интервал. После него программа
предлагает продолжить работу; при отказе или отсутствии ответа в течение минуты
токен освобождается. Для одинакового таймера на всех компьютерах при установке
укажите одну общую сетевую папку для `usage.json`.

## Установка и служба

Обычный вариант для пользователя — запустить Windows-установщик:

```powershell
dist\DiskControl-Setup.exe
```

Он запросит права администратора через UAC и выполнит рабочее размещение:

- копирует `DiskControl.exe`, `DiskControl.Admin.exe`, `dkcl64.exe` и `dkcl.ini`
  в `C:\Program Files\DiskControl`;
- создаёт `C:\ProgramData\DiskControl\allow.json` и `C:\ProgramData\DiskControl\logs`;
- настраивает ACL: пользователям чтение/запуск, администраторам изменение;
- регистрирует `dkcl64.exe` как службу Windows `dkclient`;
- создаёт ярлыки в меню Пуск и, по умолчанию, на общем рабочем столе.
- регистрирует DiskControl в **Программы и компоненты** Windows для удаления.

Запасной ручной запуск установки из консоли администратора:

```powershell
install.cmd
```

Полезные варианты:

```powershell
install.cmd -SkipBuild
install.cmd -NoStartService
install.cmd -NoDesktopShortcut
```

Сформировать установщик и переносимый zip-пакет:

```powershell
build-installer.cmd
```

Результаты будут лежать здесь:

```powershell
dist\DiskControl-Setup.exe
dist\DiskControl-Installer.zip
```

Удаление приложения и службы доступно через:

- **Параметры Windows → Приложения** или **Программы и компоненты**;
- ярлык **Uninstall DiskControl** в меню Пуск;
- ручной скрипт:

```powershell
uninstall.cmd
```

Чтобы удалить ещё и `C:\ProgramData\DiskControl` с политикой и логами:

```powershell
uninstall.cmd -RemoveData
```

`dkcl.ini` нужен штатному клиенту `dkcl64.exe` при запуске как службы.
Наше разграничение доступа хранится отдельно в `allow.json`.

## SmartScreen и подпись

Если Windows показывает “Система Windows защитила ваш компьютер”, это означает,
что `DiskControl-Setup.exe` не подписан доверенным издателем или ещё не имеет
репутации у Microsoft SmartScreen.

Для теста можно нажать **Подробнее → Выполнить**, но для нормального
распространения нужно подписать EXE сертификатом подписи кода организации.
Сборка уже поддерживает подпись:

```powershell
build-installer.cmd -CertificateThumbprint "THUMBPRINT"
```

или PFX-файлом:

```powershell
build-installer.cmd -CertificatePath "C:\Certs\company-code-signing.pfx" -CertificatePassword "PASSWORD"
```

Лучший вариант против SmartScreen — EV Code Signing или Microsoft Trusted
Signing. Обычный OV-сертификат тоже покажет издателя, но репутация может
набираться постепенно.

## Если админка закрывается сразу

Для компьютеров без Visual Studio Release-сборка собирается со статическим MSVC
runtime, поэтому отдельный VC++ Redistributable обычно не нужен. Если
`DiskControl.Admin.exe` всё равно закрывается сразу:

1. Используйте свежий `dist\DiskControl-Installer.zip`.
2. Запустите `diagnose.cmd` на проблемном компьютере.
3. Проверьте свежий лог:

```powershell
C:\ProgramData\DiskControl\logs\startup-YYYYMMDD.log
```

Если такого файла нет вообще, приложение может быть заблокировано антивирусом,
AppLocker/политикой запуска или запущено из старого пакета.

## Администрирование allow.json

В C++-версии теперь две отдельные утилиты:

- `DiskControl.exe` — пользовательская утилита. Только читает политику и
  позволяет подключать/отключать разрешённые токены.
- `DiskControl.Admin.exe` — админская утилита. Показывает полный список,
  ищет токены, открывает файл политики и сохраняет доступ пользователя по
  отмеченным галочкам.

Без параметров обе утилиты используют основной файл политики:

```powershell
C:\ProgramData\DiskControl\allow.json
```

При необходимости путь можно переопределить явно:

```powershell
DiskControl.exe --policy "D:\Configs\allow.json"
DiskControl.Admin.exe --policy "D:\Configs\allow.json"
```

Локальные `allow.json` и `allowlist.json` больше не подхватываются
автоматически. Их можно использовать только через `--policy` или кнопку
**Открыть конфиг** в админской утилите.

Если в админской утилите открыт битый или структурно некорректный JSON,
`DiskControl.Admin.exe` сохраняет старое содержимое рядом как
`*.invalid-YYYYMMDD-HHMMSS.bak` и заменяет файл пустой валидной политикой:
`pipeName = dkclient`, `refreshSeconds = 5`, `userAssignments = []`.

Чтобы сформировать доступ пользователя:

1. Откройте `build\x64\Release\DiskControl.Admin.exe`.
2. При необходимости нажмите **Открыть конфиг** и выберите нужный `allow.json`.
3. В поле **Пользователь** введите имя в формате `DOMAIN\user` или `user`.
4. Дождитесь полного списка токенов.
5. Найдите нужные токены через **Поиск** по `Endpoint`, имени или продукту.
6. Отметьте галочками токены, которые должны быть доступны этому пользователю.
7. Нажмите **Сохранить доступ**.

После этого админская утилита обновит файл политики:

- если блок для пользователя уже есть, его `allowedDevices` будет заменён
  текущим набором отмеченных токенов;
- если блока нет, будет создан новый элемент в `userAssignments`;
- короткое имя `user` совпадает с существующим блоком `DOMAIN\user`.

Колонка **Доступ** и галочки показывают доступ именно для пользователя,
указанного в поле **Пользователь**, на основании открытого файла политики.
Клик по заголовку любого столбца сортирует таблицу по этому столбцу.

Кнопки **Разрешить выбранные** и **Убрать выбранные** оставлены как быстрые
операции для выделенных строк. Основной сценарий редактирования - галочки и
**Сохранить доступ**.

Экспорт **CSV** нужен для Excel, сверки и инвентаризации. Экспорт **JSON** нужен
для технической диагностики, сравнения выгрузок и дальнейшей обработки
скриптами. Экспортируется текущий вид таблицы, включая применённый поиск.

## Ограничения безопасности

Оборудование не обеспечивает требуемую матрицу доступа, поэтому проверка
выполняется на компьютере пользователя. Текущая версия является клиентским
контроллером, а не неотключаемой системой защиты.

Пользователь сможет обойти политику, если он может:

- изменить файл политики или исполняемые файлы приложения;
- запустить штатный интерфейс `dkcl64.exe`;
- самостоятельно отправить команду в `\\.\pipe\dkclient`;
- работать с правами локального администратора.

Для рабочего развёртывания файлы программы и политики необходимо разместить
в каталоге, доступном обычным пользователям только для чтения. Изменение
политики должно быть разрешено только администраторам.

Для строгого технического запрета потребуется второй этап: служба Windows,
работающая под отдельной учётной записью. Только служба должна иметь доступ к
клиенту производителя, а пользователи должны обращаться к службе через
собственный защищённый канал. Служба будет проверять пользователя и
`endpoint` перед каждой командой `USE`.

## Результаты анализа исходника производителя

- `DKCLHelper` работает через `\\.\pipe\dkclient` и сам не реализует
  USB-over-IP.
- Команда `LIST` возвращает адреса устройств вида `SERVER-Gr-N.PORT`.
- Из ответа `DEVICE INFO` пример извлекает только `NICKNAME`, `IN USE BY`
  и `PRODUCT`.
- Серийный номер USB, `VID` и `PID` опубликованный пример не предоставляет.
- Штатный пример показывает все устройства из `LIST` и не проверяет белый
  список перед командой `USE`.
- В примере производителя указатель на локальный объект `IPCClient`
  передаётся периодическому таймеру GTK. После завершения обработчика этот
  указатель может стать недействительным. В `DiskControl` для каждой команды
  создаётся отдельное подключение к каналу.

Таким образом, доступная идентификация ключа выполняется по адресу
`endpoint`, а также, при необходимости, по `nickname` и `product`.
